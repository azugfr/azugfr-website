## 0. Ground rules for the implementer

1. **Facts only.** Every name, title, role, company, link, photo URL and bio must come from the research JSON files, the raw research HTML, or text already in the repo. Translating a fact from FR to EN (or EN to FR) is allowed. Writing new facts is not: no invented bios, abstracts, companies or photos.
2. **Keep the content model:** one JSON file per entry, canonical `locale: "fr"`, other-language overrides under `translations.en`.
3. **Keep the design language:** Tailwind, Azure blue `#0078D4`, white cards with `border-gray-200 rounded-xl`, gray-50 alternating sections.
4. **Strings:** new UI strings go in `src/data/i18n/{fr,en}.ts`. Existing inline `locale === "fr" ? … : …` strings may stay.
5. **Dates:** event JSON stores **local wall-clock time without offset** (e.g. `"2026-06-08T18:30:00"`) plus `"timezone": "Europe/Paris"`. Never put an offset in content files. The new `src/lib/dates.ts` handles the conversion.
6. **Typography:** keep the source punctuation in titles (e.g. `’` U+2019 in `l’IA`). Only fix brand casing (`Github` → `GitHub`) and obvious accents (`deboguent` → `déboguent`).
7. **Gates after every WP:** `npx vitest run`, `npx astro check` (0 errors), `npm run build`.
8. **Copy research for provenance:** put `meetup-talks.json` (and `organizers.json` when it exists) into `docs/research/2026-11/`. Do not commit the raw HTML.

## WP1 — Date utilities + status derived from dates (bug 1)

### Files

**NEW `src/lib/dates.ts`**
- `hasOffset(s: string): boolean`
  - regex `/(Z|[+-]\d{2}:?\d{2})$/i`
- `toIsoWithOffset(local: string, timeZone = "Europe/Paris"): string`
  - If the string already has an offset, return it unchanged.
  - Otherwise, find the zone offset at that wall-clock time:
    1. Treat the components as UTC: `const guess = new Date(local + "Z")`.
    2. Read the offset with `new Intl.DateTimeFormat("en-US", { timeZone, timeZoneName: "longOffset" }).formatToParts(guess)` → `"GMT+02:00"` (`"GMT"` alone means `+00:00`).
    3. Append `±HH:MM` to `local`, normalising seconds to `HH:MM:SS`.
  - DST-boundary imprecision (±1h on two nights per year) is acceptable.
- `toInstant(value: string, timeZone = "Europe/Paris"): Date`
  - `new Date(toIsoWithOffset(value, timeZone))`
- `formatEventDate(value, locale, variant: "date" | "dateLong" | "dateTime" | "time", timeZone = "Europe/Paris"): string`
  - Uses `toLocaleString(locale === "fr" ? "fr-FR" : "en-GB", { timeZone, ... })`:
    - `date` → `{year:"numeric",month:"long",day:"numeric"}`
    - `dateLong` → adds `weekday:"long"`
    - `dateTime` → `dateLong` + `hour:"2-digit",minute:"2-digit"`
    - `time` → `{hour:"2-digit",minute:"2-digit"}`
- `getBuildNow(): Date`
  - `process.env.AZUG_NOW ? new Date(process.env.AZUG_NOW) : new Date()`
  - The env override is for deterministic tests and builds.

**REWRITE `src/lib/content/eventStatus.ts`**
```ts
export type DerivedStatus = "upcoming" | "past" | "cancelled";
export function deriveEventStatus(
  entry: { status?: string; startDate: string; endDate?: string; timezone?: string },
  now: Date = getBuildNow(),
): DerivedStatus {
  if (entry.status === "cancelled") return "cancelled";
  const tz = entry.timezone ?? "Europe/Paris";
  const end = entry.endDate
    ? toInstant(entry.endDate, tz)
    : toInstant(entry.startDate.slice(0, 10) + "T23:59:59", tz); // no end → end of start day
  return end.getTime() >= now.getTime() ? "upcoming" : "past"; // an ongoing event counts as "upcoming"
}
```
The stored values `"upcoming"` and `"past"` are **ignored**.

## Things I found that the audit did not mention (already built into the plan above)

1. **Undefined Tailwind classes.** `azure-200` and `azure-800` are used in several places but not defined in `tailwind.config.mjs`, so those borders and hover colours never render. The configured `azure-600` is `#2563eb`, not Azure blue `#0078D4`. Fixed in WP4.
2. **Wrong hreflang.** `BaseLayout`'s hreflang alternate always points at the other language's home page.
3. **Language toggle loses the page.** `LanguageToggle` ignores `currentPath`, so switching language always returns to the home page.
4. **Missing `canonicalUrl` on 5 pages:** home, search, news index, news detail and resources. On those pages the locale switch falls back to the home page.
5. **Dates depend on the build machine's time zone.** Content dates have no offset and are formatted with the machine's time zone, while the Meetup sync script writes dates with an offset. Fixed with `src/lib/dates.ts`.
6. **Schemas can't be loaded in vitest.** The schemas import `z` from `astro:content`, a virtual module vitest cannot load. Switching to `astro/zod` lets the integrity tests validate content with the real schemas.
7. **Playwright browser:** use the system Chromium (`/opt/pw-browsers/chromium` in containers) or `npx playwright install chromium` locally; CI installs it explicitly.
8. **Static builds freeze status.** Event status is fixed at build time, so the deploy needs a daily rebuild. GitHub only runs scheduled workflows from the default branch, so that rebuild starts working after cutover.
9. **No event is upcoming as of today.** The research has no event after 2026-09-29, so the home page will show the "Next meetup coming soon" message.
